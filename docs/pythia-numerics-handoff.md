## What the new tests establish

- Diagnostic trace of 70M block 29 has **bit-identical final logits** to the
  installed baseline. Tracing is compiled out unless `LEAF_DIAGNOSTIC_TRACE`
  is defined. Normal builds have no trace branches or file I/O.
- The first stage exceeding the existing `atol=rtol=2e-4` is **layer index 3
  attention context**, with maximum absolute error 0.002075851 and 1,750
  violations. Earlier layers have nonzero roundoff but no tolerance violations.
  This identifies the first material amplification, not the first rounding error.
- A NumPy replay of the native AVX2 eight-lane dot-product reduction and two
  scale multiplications reproduces that context within 1.1921e-6, even while
  using Torch softmax/value multiplication. Reduction order matters materially
  on these inputs; the unmasked score matrix has values of order tens of thousands.
- On **the same complete 70M block**, PyTorch SDPA also fails the existing
  logit tolerance against PyTorch eager: **81 violations**, max error 0.02001953.
  Leaf baseline has **101 violations**, max error 0.01347351. All three agree
  on the 127 scored next-token predictions for this block.
- On block 10, all implementations pass elementwise tolerance, yet Leaf differs
  from eager on one scored argmax and SDPA differs on two. This shows why raw
  logit allclose and token agreement must remain separate checks.
- A diagnostic-only direct-scale candidate uses `dot / sqrt(head_dim)` instead
  of `dot * quarter_root_scale * quarter_root_scale`. It reduces 70M block 29
  violations from 101 to 78, but **still fails**; max absolute error increases
  to 0.01452637. Do not ship it as a fix or call it a performance improvement.
- A Torch model converted to float64 provides another sensitivity comparison,
  not an exact oracle: Transformers still explicitly computes some rotary work
  in float32. Leaf has 18 violations against that diagnostic on block 29,
  direct-scale candidate 5, eager 76, SDPA 185. This is input-specific evidence,
  not proof that any runtime is globally more accurate.

The evidence supports FP32 attention-score sensitivity across implementations.
It does **not** prove the remaining Leaf errors harmless or certify the full
corpus. The Mistral sliding window is not involved: Pythia uses full attention.

The 160M block 31 comparison also completed: baseline has one violation against
eager, SDPA has zero, and the direct-scale candidate has zero. The float64
diagnostic itself has one violation against eager at the same logit. Baseline
Leaf is within tolerance against float64 on this block. The candidate still
fails 70M, so this is not sufficient to promote it. All implementations agree on
the 127 scored next-token predictions in the 160M block.

## Files and reproduction

- `tools/trace_pythia_logits.py`: validates fixture/model/artifact hashes,
  traces one saved input, and checks final-logit equality with the baseline.
- `tests/native/decoder_trace.h` and trace calls in `engine/src/decoder.cpp`:
  compile-time diagnostic only. One forward per fresh output directory.
- `tools/diagnose_pythia_reference.py`: eager/SDPA/float64 comparison with
  optional native candidate. Atomic checkpoint after each saved block.
- Local working directory: `build/pythia-trace-20261014/`.
- `block29-rotary/trace.json`: layer errors and executable hashes.
- `block29-rotary/isolated.json`, generated by local `isolate.py`: identical-input
  attention replay. This local prototype is not a general validation tool.
- `reference70.json`: completed comparisons for blocks 29 and 10.
- `reference160.json`: completed comparison for block 31.
- `direct-scale/`: disposable candidate header/source/executable, not release
  code. Copies replace the score multiplication in the vector header and scalar
  transformer source with `1/sqrt(dim)` and `1/sqrt(head_dim)`, respectively.
  This bypasses the shared graph scale contract and must never be packaged.

Build the trace (MinGW g++, repository root):

```powershell
g++ -std=c++17 -O3 -DNDEBUG -DLEAF_DIAGNOSTIC_TRACE=1 -pthread -static -static-libgcc -static-libstdc++ -I engine/include engine/src/decoder.cpp engine/src/main_decoder.cpp engine/src/kv_cache.cpp engine/src/kernels/transformer.cpp -o build/pythia-trace-20261014/leaf_decoder.exe -lpsapi
$env:LEAF_CACHE_DIR="$PWD/build/manual-model-cache"
python tools/trace_pythia_logits.py --quality-record build/output-quality-20261013/pythia70/quality.json --tokens build/output-quality-20261013/pythia70/tokens.json --block 29 --executable build/pythia-trace-20261014/leaf_decoder.exe --baseline build/output-quality-20261013/installed/leaf/bin/leaf_decoder.exe --output build/pythia-trace-20261014/new-trace
```

The output directory must be fresh. Reference checks need Torch/Transformers;
inference does not. Python/native temporary-file access may require execution
outside the sandbox. Existing weights are local; no model download is needed.
